# 公共约定（ specs/* 共用）

本文件集中定义所有功能规格共享的跨功能约定。各功能规格（specs/*.md）只声明本功能的独有内容，共享约定一律引用本文件，不得复制。

权威边界：端点与 schema 定义权在 API.md；表结构与枚举定义权在 DATABASE.md；编码规则在 AGENTS.md。本文件不重复这些定义，只做功能规格的公共行为约定。

## 角色与权限

角色枚举定义见 DATABASE.md `users` 表（`admin` / `supervisor` / `inspector` / `viewer`）。各功能规格不再重复角色表，只声明本功能各操作所需的最低角色。

通用权限规则：

- `viewer` 只读；`inspector` 可创建与编辑自己的业务记录；`supervisor` 可审阅与定稿；`admin` 拥有全部权限并管理用户与知识库。
- 数据归属规则见 DATABASE.md「数据归属」章节；前端不得仅凭隐藏导航或按钮做授权，所有授权以后端校验为准。

## 异步任务与轮询协议

所有耗时操作（生成、索引、重建）一律走异步任务：提交端点返回 `{task_id}`，前端轮询 **`GET /api/tasks/{task_id}`**。

- 响应 schema、状态枚举（`pending` / `queued` / `processing` / `completed` / `failed` / `cancelled`）、`task_type` 取值见 API.md §8 与 DATABASE.md `ai_tasks` 表。
- 任务到达终态（`completed` / `failed` / `cancelled`）后前端必须停止轮询。
- 页面刷新或重新进入后，前端必须能通过任务查询恢复进度展示，不丢失进行中的任务状态。
- `completed` 时从 `result_data.record_id` 取业务记录 ID 并跳转或加载详情。
- `failed` 时展示可读的 `error_message`，不得静默失败。
- 重试与取消的语义（哪些状态可 retry / cancel）见 API.md §8，各规格不重复定义。

## 文件上传

类型白名单、大小上限、四重校验（扩展名 / MIME / 文件签名 / 大小）与错误码见 API.md §9，各规格只声明本功能使用哪个类别。

- 前端上传前按白名单预校验扩展名与大小。
- 必须展示上传进度；后端返回的可读错误必须原样展示，禁止静默忽略失败。

## AI 通用约束

适用于所有涉及 AI 的功能（详细组件边界与工作流见 AI_CONTEXT.md）：

- AI 不得编造内容：无依据的字段留空或标注缺失，禁止虚构事实、日期、法规条款。
- 证据与生成内容分离：原始文件、OCR/转写原文与 AI 生成的结构化内容分开保存、界面可区分。
- Prompt 只存在于后端，禁止下发到前端；模型与 provider 一律来自环境变量配置，禁止硬编码。
- AI 输出必须是结构化 JSON（约定见 AI_CONTEXT.md），解析失败按失败处理，不得把原始文本直接当结果展示。
- AI 生成内容在用户定稿前必须可编辑；重新生成必须保留历史版本，不得覆盖。

## 安全与日志

- 响应与日志中不得暴露内部存储路径；文件访问通过后端签发，下载走签名 URL 或受控端点。
- 日志不得记录密码、token、文件内容等敏感信息。
- 上传的临时文件与处理中间产物必须在使用后清理。
- 通用安全规则见 AGENTS.md；密码哈希、软删除等数据库级规则见 DATABASE.md。

## API 路径约定

- 业务路径一律单数（`/api/inspection-record`），禁止切换为复数形式。
- 所有错误响应使用统一错误信封（见 API.md §1），前端按 `error.code` 处理、按 `error.message` 展示。

## 通用验收标准

每个功能规格的功能性验收标准之外，以下各项对所有功能适用，各规格不再重复：

- 页面具备 loading / empty / error 三态，无硬编码假数据。
- 构建、lint、类型检查全部通过；后端 migration、测试通过。
- 不满足权限的操作被后端拒绝并返回可读错误。
