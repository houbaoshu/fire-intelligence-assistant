# Photo Report（拍照报告）

## 目的与范围

拍照报告将一段检查视频转换为结构化、可逐张审阅的证据图片集（每张带简洁 caption），再由后端生成 Word 文档。它免除检查人员逐张拍照与人工撰写图片说明的工作量，同时保留对每张入档图片与每句文字的人工审阅。

范围（v1）：

- 一次上传一段检查视频，附可选补充说明 `remarks`；
- 提交异步生成任务并跟踪进度；
- 后端抽帧、去重与质量筛选产出候选帧，执行图像识别（Vision + OCR + LLM），产出 caption、识别地址、识别违规等草稿；
- 列表查看既有报告；
- 审阅报告信息，选择、排除、排序图片并编辑 caption；
- 保存结构化报告，生成并下载 Word 文档。

范围外：照片直传（不经抽帧）、PDF 导出、自动定稿、对外分享链接。

## 角色与权限

角色与权限通用规则见 specs/_common.md。本功能最低要求：创建与编辑须 `inspector` 及以上；定稿须 `supervisor` 或经后端授权；报告、源视频与生成文档的访问一律以后端鉴权为准。

## 功能要求

### 上传与提交

- 一次上传一段检查视频（视频类别，白名单与大小上限见 API.md §9），附可选 `remarks`。
- 提交前展示文件名、大小与预校验结果，可更换或移除。
- 上传进度与 AI 处理进度为两个独立状态；防止重复并发提交。

### 任务进度

- 提交返回 `task_id`，轮询、终态与刷新恢复规则见 specs/_common.md；`completed` 后加载结构化草稿与候选帧图片集。
- 部分候选帧分析失败时保留可用结果并明确标记缺失分析，不得静默丢弃。

### 图片集（Gallery）

每张图片展示：预览、源视频时间戳（`frame_timestamp`）、选中状态、caption 草稿、识别地址、识别违规、人工复核标记。

可用操作：大图预览、纳入/排除、调整顺序、编辑 caption、更正地址与违规文字、保存。

### 文档生成

- 仅选中（`is_selected`）的图片进入最终文档；图片顺序与 caption 以保存后的审阅状态为准。
- 报告至少含一张选中的有效图片才允许生成文档；`sort_order` 必须唯一且归一化。
- 更新请求中的图片 `id` 必须属于同一报告，由后端校验。
- 下载使用后端生成的文件；重新生成按 DATABASE.md 保留历史版本。

## 业务规则（本功能独有）

### 照片筛选

- 入档照片必须清晰呈现相关检查证据。
- 模糊、过暗、过渡、遮挡、重复或高度相似的照片应予排除（抽帧阶段自动初筛，审阅阶段用户可再排除）。
- 报告须包含足以支撑内容的证据，同时避免不必要的重复。
- 从报告中移除照片不得自动删除仍被其他记录引用的源文件。

### 违规描述（一张照片一个违规）

- 每张照片至多描述一个主要违规。
- 一张照片呈现多个互不相关的问题时，选择最相关的一项；证据允许时用不同照片分别呈现。
- caption 不得拼凑无依据或互不相关的违规。
- caption 必须简洁、客观、写实。

### 地址一致性

- 除非明确确认存在多个地点，检查地址在报告内须保持一致。
- 用户确认的数据优先于 OCR 推断。
- 缺少用户确认数据时，使用可靠的 OCR 结果与旁证。
- 地址证据冲突或不完整时必须转人工复核。
- 系统绝不得编造地址。

### 人工审阅

- 所有 AI 生成的 caption、违规与地址均为草稿。
- 定稿前用户必须能编辑、替换、排除或重新生成草稿。
- 未经明确授权的审阅操作，任何 AI 生成报告不得定稿。
- 生成文档必须反映保存后的审阅状态，而非较早的 AI 输出。

### Caption 规则

caption 必须：

- 描述可见的主要问题；
- 仅在有依据时标注地点；
- 使用中立、专业的语言；
- 避免推测与多余叙述；
- 长度适配文档模板；
- 不得断言无依据的法律结论。

界面文案为中文，caption 示例从略。

## 字段清单

字段定义权在 DATABASE.md，本功能关键字段：

- `photo_reports`：`title` / `inspection_unit` / `inspection_address` / `violation_summary` / `status` / `source_task_id`。
- `status` 取值：`draft` / `processing` / `generated` / `reviewed` / `finalized` / `archived` / `failed`。
- `photo_report_images`：`caption`（可编辑图片说明）/ `detected_address` / `detected_violation` / `is_selected`（是否入档）/ `sort_order`（显示顺序）/ `frame_timestamp`（源视频时间戳，秒）。

## UI 结构

页面按 `上传区 → 任务进度 → 报告信息 → 可选择图片集 → caption 与违规编辑 → 保存/生成/下载操作` 组织；列表页为报告入口。

关键交互：

- 拖拽与文件选择器上传，上传与 AI 处理进度分开显示；
- 大图预览对话框；预览失败显示占位图且不影响文字编辑；
- 选中/未选中控件可访问，不单独依赖颜色表达；排序支持键盘操作或等效无障碍方案；
- 未保存变更状态可见，放弃编辑前需确认；
- 不确定或冲突的识别结果展示人工复核标记。

## API 端点

请求/响应 schema 见 API.md：

- `POST /api/photo-report/generate` — 生成，`multipart/form-data`：`video`（必填，单个检查视频）+ `remarks`（可选），返回 `{task_id}`。
- `GET /api/photo-report` — 列表（分页）。
- `GET /api/photo-report/{id}` — 详情（`images` 元素含 `frame_timestamp`）。
- `PUT /api/photo-report/{id}` — 更新；图片按 `id` 逐项更新，仅 `caption` / `is_selected` / `sort_order` 可编辑，不涉及图片增删。
- `GET /api/photo-report/{id}/download` — 下载 Word 文档。
- `GET /api/tasks/{task_id}` — 任务轮询（协议见 specs/_common.md）。

## 数据影响

涉及表：`photo_reports`（报告级结构化数据）、`photo_report_images`（图片选择/顺序/caption/识别结果）、`uploaded_files`（源视频与生成文件元数据）、`ai_tasks`（异步任务）、`generated_documents`（版本化输出文档）、`audit_logs`（关键操作审计）。

二进制存对象存储，数据库只存元数据与结构化报告状态。

## 验收标准

- [ ] 一段合法视频创建一个生成任务，完成后经抽帧产出候选帧图片集与结构化草稿。
- [ ] 每张展示图片可追溯其来源（源视频时间戳）与识别结果。
- [ ] 用户可编辑 caption、地址与违规文字，可选择、排除、预览图片并无障碍地排序。
- [ ] 冲突或不确定的地址与违规识别结果要求人工复核。
- [ ] 系统不编造未见的违规、设备或地点。
- [ ] 生成文档只含选中图片，顺序与 caption 均与保存后的审阅状态一致。
- [ ] 审阅后的结构化数据独立于生成文件持久保存。
- [ ] 通用验收标准见 specs/_common.md。
